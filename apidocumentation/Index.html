Introduction

The purpose of this document is to give agents, and specifically their IT Technical departments, an insight into how Cyberlogic e-Tourism Platform set of XML web services works and what steps need to be completed in order to develop the interface with the platform.

This document includes a simple guide to implementing each XML web service, with code examples in C#, as well as some snap shots of its use in an XML posting application.

After that we will look into each service in detail, describing the function of the service, a link to the service and a listing of all the variables used in the request functions along with descriptions.

Finally, there are references to example XMLs, and XSD requests and responses, which are included along with this document. Please bear in mind that these are only guidelines designed to support your implementation and, due to the dynamic nature of the system’s development, may differ and change over time.

Using the Web Service

A certain procedure is required to take place in order to be able to use any of the web services.

Firstly, a user account is required to access any of the functions contained within the web service. These details are normally acquired through the web service distributer - system administrator.

A list of all of the functions on the web service can be typically found at the following web address: http://www.link-url.com/services/webservice.asmx

In the analysis below, links are included to the XSDs for each function, which should be used to produce appropriately formatted XML. The service will also return informed error messages that should accurately identify any problems occurred with the format of the XML or with system failures & errors.

There are many ways to the connect to the web service, and most methods are supported including simple HTTP GET, HTTP POST, REST, and SOAP versions 1.1 and 1.2 (some helpful instructions can be found on the links that have been included with each function analysis below).

For reference purposes, the following code illustrates how to connect to the web service using a simple http request (POST) in C#:

						
                                string strWebServiceUrl = "http://www.link_url.com/services/webservice.asmx/HotelInfo";
                                string strXmlRequest = "xml=usernamepassword123";
                                string strXmlResponse = GetXmlData(strWebServiceUrl,strXmlRequest); 
                                public string GetXmlData(string strWebServiceUrl, string strXmlRequest)
                                {
                                    HttpWebRequest httpReq = (HttpWebRequest)WebRequest.Create(strWebServiceUrl);
                                    httpReq.Method = "POST";
                                    httpReq.ContentType = "application/x-www-form-urlencoded";
                                    byte[] xmlbytes = Encoding.UTF8.GetBytes(strXmlRequest);
                                    httpReq.ContentLength = xmlbytes.Length;
                                    StreamWriter myWriter = null;
                                    myWriter = new StreamWriter(httpReq.GetRequestStream());
                                    myWriter.Write(strXmlRequest);
                                    myWriter.Close();
                                    HttpWebResponse httpResp = (HttpWebResponse)httpReq.GetResponse();
                                    Stream retStream = httpResp.GetResponseStream();
                                    StreamReader reader = new StreamReader(retStream);
                                    responseFromServer = reader.ReadToEnd();
                                    reader.Close();
                                    retStream.Close();
                                    httpResp.Close();
                                    return responseFromServer;
                                }

Regarding the booking process, it is important to study the Reservation function and to understand all of the requirements that are necessary for each service. It is also recommended to make the use of caching where it is appropriate. There are many queries that will not change very regularly and so it would makes sense to save their responses and use the data locally to improve the performance of an application, and use less resources to perform simple tasks
